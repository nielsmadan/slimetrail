# Formats and behavior

Compatibility is checked with synthetic normalized-entry and query goldens generated from the supplied `check-agent-logs` reader, plus independent tests of indexing, roots, failures and query behavior. This establishes coverage for the fixture formats below, not every historical agent release. Devin has no reference reader; its expected entries in `tests/readers_devin.rs` are hand-written from probe observations of Devin CLI 3000.14. No real transcript is a fixture. Reference generators are in `tests/fixtures/jsonl/generate.py` and `tests/fixtures/query/generate.py`.

## Supported stores

| Agent | Supported data | Boundaries |
| --- | --- | --- |
| Claude Code | Project JSONL, messages/tools/metadata, child sessions and recognized Claude ringleader archive records | Other agents' archived transcripts go to their own readers, never to Claude; no store mutations |
| Codex | Session/rollout JSONL, plain or zstd-compressed (`.jsonl.zst`, the plain file wins when both exist), native archived sessions, ringleader-archived rollouts, header identity, title index, message/tool/reasoning records | Child ID is distinct from parent `session_id`; structured tool payload rendering differs from Python repr |
| Cursor | JSONL under `agent-transcripts`, companion `meta.json`, private chat `store.db` metadata; ringleader-archived transcripts with their chat directory (`<id>/meta.json`, `<id>/store.db`) beside them | Legacy role-delimited `.txt` transcripts produce incomplete diagnostics; protobuf message blobs are not decoded; missing tool output is not reconstructed |
| Devin | CLI `sessions.db` (`sessions`, `message_nodes`, `subagent_heads`): the live chain from `main_chain_id`, history moved off it by compaction, subagent chains as child sessions `devin:ID/AGENT` | System prompt, rules and skill-listing nodes are not indexed; reverted turns and superseded node copies are excluded; `/fork` copies are independent sessions without `parent_ref`, so shared history matches in both and its human prompts count in both sessions' timeline spans; query refreshes reparse a session only when its change key (node count, maximum node and row ids, session row, subagent head) changes, so an in-place edit that keeps the key is picked up only by the content-hash sweep in `slimetrail index`; end-of-session ATIF `transcripts/`, Devin Desktop `cli-next/` and `DEVIN_SESSION_STORE=files` are not read |
| Droid | Session JSONL and companion settings metadata, live or ringleader-archived with the settings beside the transcript | Automation/exec settings affect human prompt accounting and fingerprints |
| OpenCode | SQLite session/message/part schema (1.x), optional parent/archive fields and project cwd fallback | Legacy file-only storage is diagnosed unsupported; unsupported schema or unstable snapshot produces incomplete coverage; the 2.x `session_v2`/`session_message` tables are not read, so sessions created only by OpenCode 2.x are missing; the whole database is one fingerprint, so any OpenCode write reparses every session, and a database over about 1.26 GB (at the default compact rate) gets `index_required` on non-interactive queries after each write until `slimetrail index` runs, while a terminal query reparses it inline or prompts (see [integrations](integrations.md#migration-checks)) |
| Pi | Session JSONL, live or ringleader-archived, with canonical header ID, messages, tools and metadata | Filename guesses cannot replace a known header identity |

Required selected stores that are missing or unreadable are incomplete. The optional ringleader archive may be absent normally. Each archived transcript is attributed to an agent only by a positive format marker; one no reader recognizes is diagnosed `archive_format_unknown` when Claude is selected, or, for a compressed `.jsonl.zst` that is not a Codex rollout, when Codex is selected. Cursor metadata failures are explicit; cwd is never reconstructed from a lossy project slug. A subagent marker can mark entries automated without supplying a reliable `parent_ref`. Unknown records with meaningful searchable content can normalize to metadata; records without searchable content may be ignored. A final JSONL record without a trailing newline that is not valid JSON is treated as still being written and ignored while the file was modified less than 10 minutes before the command started, and the source is reread on every refresh until then; after that it counts as malformed. Stable malformed records preserve usable entries with diagnostics; repeated source churn excludes stale entries.

Store root and environment precedence is in the [README](../README.md#stores-and-index). Tests override Codex's home as well as its sessions directory so native archive lookup cannot escape to real stores. Stored cwd paths are expected to be absolute; a nonstandard stored `~` is not expanded. CLI `--cwd ~` is expanded from captured HOME.

## Search and read

Search uses smart case by default, for literal and regex queries and for text and JSON output alike: a query with no uppercase letter matches case-insensitively, and one containing an uppercase letter (Unicode `is_uppercase`) matches case-sensitively. For a literal query every character counts. For `--regex` only literal characters and character-class literals and range endpoints count, so `\W`, `\S`, `\p{Lu}`, `[[:upper:]]` and the `i` in `(?i)` leave a pattern case-insensitive, while `[A-Z]`, `[a[B]]` and `\x41` make it case-sensitive. A regex that does not parse is rejected as invalid. `-i`/`--ignore-case` forces case-insensitive matching, `-s`/`--case-sensitive` forces case-sensitive matching and `-S`/`--smart-case` selects smart case explicitly; the last of the three given wins, so `-i -s Needle` is case-sensitive and `-s -i Needle` is not. `-F`/`--fixed-strings` (the default) and `-E`/`--regex` likewise override each other, last one winning. Library callers choose `CaseMode::Smart`, `Sensitive` or `Insensitive` in `SearchOptions`; the CLI flags map onto it.

Case-insensitive matching uses Unicode simple case folding; it is not accent normalization or full multi-character case folding. Regex mode uses Rust regex syntax, including supported inline flags: `(?i)` and `(?-i)` inside a pattern override the case mode selected by the flags or by smart case for the part of the pattern they cover. It has no look-around/backreferences. Empty literal queries are rejected. Zero-width regex matches are ignored. Matches are non-overlapping, counted separately per title/entry, and grouped by session. A query that begins with `-` must follow `--`, as in `slimetrail search -w -- '-foo'`.

`-w`/`--word-regexp` keeps only matches whose neighbouring characters are not word characters (Rust regex's Unicode `\w`: letters, marks, digits, connector punctuation and join controls); the start or end of the text counts as a non-word neighbour. Like ripgrep it uses half word boundaries, wrapping the escaped literal or the regex as `\b{start-half}(?:PATTERN)\b{end-half}`, so the match itself may begin or end with non-word characters: `-w rust` matches `rust code` but not `trust`, `rusty` or `rust_`, and `-w 'Result<T>'` matches `use Result<T> here`. With `--regex` the pattern is validated on its own before it is wrapped. A `-w` regex that can match the empty string counts only its non-empty matches.

`-l`/`--refs-only` changes text output to the `ref` (`agent:id`) of each returned session, one per line in result order, still capped by `--max-results`. Nothing else goes to stdout: no header, and no `No matches.` line, so an empty result prints nothing. Refs are escaped exactly like other text output, with terminal and bidirectional controls shown as escapes. Diagnostics still go to stderr and the exit code is unchanged: 0 when complete, 1 when incomplete. Combining it with `--format json` is a usage error (exit 2, with the usual fatal JSON envelope), since JSON results already include `ref`. `--max-snippets` and `--context` have no effect with it.

Search coverage is set by `coverage` in the config file: `compact` (the default) or `full`.

- **Compact** searches everything except reasoning and the early part of long tool results. Only the last 2 KB of each tool result is searched. Reasoning (metadata entries with subtype `reasoning`) can still be read with `read --mode full`, but it is not searched. `--kind tool` matches tool calls in full and tool results only in their last 2 KB. A tool result is a Claude content entry made only of `tool_result` blocks, or a string `toolUseResult`. It is also a Codex `function_call_output` or `custom_tool_call_output`, a Pi/Droid `toolResult`/`tool` message, a Cursor entry made only of tool-result blocks, or a Devin `tool_result`. An entry mixing a tool call and its result is searched in full, as is an OpenCode tool part, which holds both.
- **Full** searches all stored text except Claude string `toolUseResult` values whose trimmed text repeats the same record's `tool_result`. Those duplicates are stored and readable in both coverages but never scored.

Regex anchors such as `^` apply to the searchable slice, so in compact `^` matches at the start of a tool result's last 2 KB. Snippets are taken from the same slice. A compact search adds an informational `search_coverage` diagnostic when the config does not set `coverage`; when `--kind` explicitly includes `meta` or `tool`, it adds `coverage_excluded` instead, naming the limited kind, whether or not the config sets coverage. A search whose configured coverage (compact if unset) differs from the index's adds an informational `coverage_mismatch`, on compact and full indexes alike. None of them makes the result incomplete.

Weights are native title 5, message 3, metadata 2 and tool 1 per occurrence. A native title is searched once even with an entry-kind filter. Derived titles are display-only. Score order breaks ties by last conversation timestamp descending, then agent/key; recent order breaks ties by score descending, then agent/key. Snippets follow document/entry order, with native titles first, rather than strongest-match order.

`--days` on search/sessions uses source freshness: file mtime for file-backed sessions and native update time for database-backed sessions. It does not mean "entry timestamps in the last N days." Cwd scope compares normalized lexical paths: current is equality, siblings adds equal parents, all also permits unknown cwd. `--app` is a case-insensitive cwd substring and takes precedence over scope. Filters run after a refresh of the admitted agents, so narrowing the query does not skip source health checks. A selected agent whose pending work is over the query's build limit is not refreshed; it answers from its last published state, or not at all, and the result carries `index_required` with exit 1.

Read rendering preserves original timestamps when available, emits timestamp plus `[role/kind]` headings, trims trailing whitespace from entry text, and separates blocks by blank lines. Lite includes messages, full includes messages/metadata, log includes all kinds. Character pagination preserves Unicode scalar boundaries; it is refreshed each call and does not pin a transcript revision. JSON exposes `truncated` and `next_offset`. Text pages keep the transcript slice on stdout and print `Transcript truncated; continue with --offset N` to stderr only when more text remains.

## Timeline

Timeline requires `--since` or positive `--days` (mutually exclusive). Entries are included in `[since, until)`; `--until` defaults to the captured current time. A bare until date includes that full local date by resolving the next civil midnight. Explicit offsets identify absolute instants; naive datetimes and date-only values use `--time-zone`, then `TZ`, then the IANA system zone. Ambiguous/nonexistent local datetimes are rejected with a request for an explicit offset. Local days can be 23 or 25 hours across DST; `--days N` remains exactly N × 24 hours ending at the resolved until.

Sessions must also have source freshness at least the resolved since. An old unmodified source can therefore be excluded even if its records overlap the requested window. Explicit historical until windows do not independently apply a cutoff relative to today. Entries without usable timestamps are skipped with one counted diagnostic per source, making the timeline incomplete.

An event gap at or below `--idle-minutes` stays in the same span; a larger gap starts another. The span ends at its last event, with no idle tail added; a single event has zero duration. Human prompts count only non-automated user message entries. Kind filters do not remove timeline events. Claude/Cursor child sessions with parent provenance or a `subagents` path, and Devin subagent child sessions, are excluded from timeline (Claude/Cursor to match reference behavior; Devin because subagent activity happens inside the parent session); search still includes them. Other harness child sessions remain included. A marker with no parent/path does not independently trigger that timeline exclusion.

Daily totals merge overlapping spans across all included sessions and split at civil-day boundaries in the selected zone. Summing session totals can exceed a day's union total because sessions overlap.

## Finite differences from the reference script

1. Default search is literal substring; reference regex behavior requires explicit `--regex` here. Rust regex syntax/simple folding can differ from Python, and zero-width matches are ignored. The reference always matches case-insensitively; here smart case makes a query with an uppercase letter (for `--regex`, an uppercase literal) case-sensitive unless `-i` is given.
2. The public output is a versioned CLI JSON envelope with explicit DTOs. Python consumers use subprocess JSON; importing the reference module is not the integration model.
3. All selected-source failures return incomplete coverage with exit 1, even when no usable sources remain. Fatal usage/index/runtime failures return 2. This replaces the script's differing all-agent and explicit-selector failure exits.
4. Non-string Codex tool arguments/results render as deterministic insertion-order JSON, not Python `repr`; existing string payloads remain strings.
5. The mixed ringleader archive is routed by format: Claude, Codex, Cursor, Droid and Pi transcripts are read as archived sessions of their own agent. Native Codex archives are also supported.
6. Cursor legacy text and OpenCode legacy file storage are explicitly unsupported/incomplete. No guessed Cursor protobuf decoder or synthetic tool-output reconstruction is included.
7. Native `thinking`/`reasoning` content blocks become metadata with subtype `reasoning`. Content arrays retain adjacent message/reasoning/tool runs in source order, rather than flattening reasoning into messages and collecting tools separately. This changes emitted-item ordinals for mixed blocks; lite reads exclude reasoning, and with full coverage meta-only searches score it at weight 2 (compact coverage does not search it).
8. Search coverage defaults to `compact`, which the reference script does not have: reasoning is not searched and only the last 2 KB of each tool result is, so a default search can miss matches the script finds. Set `coverage = "full"` to search all text except duplicated Claude `toolUseResult` values.

These are specific compatibility boundaries, not an exemption for unlisted discrepancies. The crate declares MSRV 1.89. Local validation is macOS; the initial implementation also passed both Linux and macOS [CI checks](https://github.com/nielsmadan/slimetrail/actions/runs/44023048762). Current CI additionally checks the manifest MSRV and release targets. There is no Windows support claim.
